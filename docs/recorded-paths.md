# 의심암귀 V0.4 — 기록된 경로 탐색 및 대형 그래프

## 기록된 경로 추적

1. 노드를 클릭하여 **근거 상세 → 이 노드에서 시작** 선택
2. 관계망에서 다른 노드를 선택하면 실제 존재하는 노드·엣지의 **최단 탐색 경로**를 보여줌
3. '관측된 관계만'을 켜면 `observed` 엣지만 허용
4. 경로의 노드 버튼을 선택해 탐색 대상을 이동하거나, 초기화하여 일반 그래프로 복귀

엣지의 화살표 방향을 바꾸지 않은 상태로 인접 관계를 양방향 탐색합니다. 즉, 경로는 **연결된 데이터의 탐색 순서이지 모델의 인과적 판단 근거 또는 숨겨진 생각이 아닙니다.** 보고/추정/수동 관계가 포함되었다면 UI에서 개별 출처 표시가 유지됩니다.

검색, 노드 종류, 시간 필터는 경로 계산에 우선 적용합니다. 그래프에 두 노드가 존재하지 않거나 연결되지 않으면 결과 없음으로 안내하고 임의 연결을 생성하지 않습니다.

## 대규모 그래프 운영

- 브라우저 그래프 캔버스는 기본적으로 최대 **600개 노드 / 1,800개 엣지**를 그립니다.
- 제한을 넘으면 선택한 노드와 경로를 우선 남기고, 연결 수가 높은 노드를 안정된 순서로 고릅니다.
- 화면에 표시하지 않은 노드·엣지의 개수를 안내합니다. 원본 데이터는 삭제되지 않습니다.
- 관계 렌즈 또는 검색으로 범위를 좁힐 수 있습니다.
- Cytoscape 인스턴스는 한 번 생성하고 노드·연결 변화에 맞춰 **차이만 갱신**합니다.
- 데이터나 구조가 변하지 않는 경로 강조, 노드 선택에서 전체 레이아웃을 재계산하지 않습니다.
- 큰 그래프(250개 노드 초과)는 원형 계층 배치로 전환해 과도한 force-layout 연산을 줄입니다.
- 노드 이동 카메라 애니메이션은 시스템의 모션 감소 설정에서 비활성화합니다.

단, 이 전략은 서버 측 클러스터링이나 WebGL 수준의 완전한 가상화를 제공하지 않습니다. 600개 노드 화면의 체감 성능과 모바일 FPS는 수동 벤치마크가 필요합니다.

```bash
npm run test

```

### 수동 확인 항목

- [ ] 출발 노드 지정 후 연결된 노드까지 선이 강조되는가
- [ ] 경로가 없는 두 그래프의 노드 선택 시 없는 경로로 표시하는가
- [ ] 관측 관계만 켜면 보고/추정/수동 엣지가 포함되지 않는가
- [ ] 라이브 데이터 추가 후 확대/이동 상태가 보존되는가
- [ ] 시스템 모션 감소 설정에서 카메라 자동 애니메이션이 멈추는가
- [ ] 600개 초과 노드의 생략 개수 배너 및 경로 우선 표시가 올바른가
