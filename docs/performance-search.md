# 의심암귀 V0.9 — 실제 구조 성능과 실행 분석

## 로컬 인덱스 검색

질문 입력창에 입력하는 검색식 예시:

- `SQL`: 포함된 문자열 검색(대소문자 구분 없음)
- `"인덱스 사용 문서"`: 따옴표 구문 검색
- `kind:model`: 모델 호출 노드만
- `evidence:observed`: 연동으로 직접 기록된 노드만
- `source:runtime`: 출처 문자열의 일부가 일치한 노드
- `trace:ABCDEF12`: 명시적인 trace ID의 접두사
- `kind:model evidence:observed`: 모든 조건 AND

한 번 입력할 때마다 전체 텍스트를 처음부터 훑지 않도록 노드의 라벨·설명·출처에서 **3글자 부분 문자열 인덱스(trigram posting lists)**를 구성합니다. 영문·한글 모두 지원하며, 1~2글자 검색은 전체 스캔합니다. 새로운 라이브 이벤트를 받아 워크스페이스가 갱신되면 메모리 인덱스를 다시 구성합니다.

검색 결과는 기존처럼 **일치하는 노드 + 실제 1단계 연결 이웃**을 보여줍니다. 숫자 표시는 직접 일치한 노드 수이므로 그래프에 표시되는 개수와 다를 수 있습니다. 이웃 관계를 인위적으로 생성하지 않습니다.

## 실행별 상세 분석

실행 ID가 있는 수집 데이터에서 **실행 ID 기준**으로 묶음을 선택하면 분석 카드가 표시됩니다.

- 기록된 이벤트·관계 개수
- 관측된 기록·오류 이벤트 수
- 가장 이른 기록과 가장 늦은 기록의 시간 간격
- 실제 기록 시간순 이벤트로 이동

이 시간은 **관측 기록의 기간**이며 모델 추론 시간이나 응답 지연시간이라고 해석할 수 없습니다. 그래프에 없는 작업이나 내부 사고를 보완하지 않습니다.

## 합성 대용량 벤치마크

```bash
npm run bench:graph
npm run bench:graph -- --quick
```

기본 데이터는 **10,000 노드와 30,000 관계**를 결정론적으로 생성하고, 메모리에서 검색 인덱스 구성·6개 검색식 반복·노드 필터링·연결 묶음 계산·화면 표시 예산·경로 탐색 시간을 측정합니다.

출력은 JSON으로 `medianMs`, `p95Ms`, 검색 인덱스 구축 시간, `heapUsedMiB`를 제공합니다. **측정 머신의 Node.js CPU 시간**으로, 브라우저 프레임 속도나 프로덕션 트래픽 성능을 보장하지 않습니다. 합성 입력만 사용하며 네트워크·실제 개인 대화 데이터는 사용하지 않습니다.

CI에서는 성능 회귀 관측 목적으로 결과를 출력합니다. 실행 환경의 편차가 있어 고정 ms 기준 실패 조건은 적용하지 않습니다.

## 제약

- 검색 인덱스는 브라우저 메모리를 사용하므로 원본 노드가 수만 개 이상일 때 메모리 프로파일링이 필요합니다.
- 한 화면 최대 600개 노드·1,800개 엣지 표시 예산은 그대로 유지합니다.
- 실제 브라우저 FPS·모바일 기기 메모리·실제 API 키를 사용한 엔드투엔드 검증은 별도 과제입니다.
- 관측·보고·추정·수동 기록 구분과 기본 원문 미수집 정책을 유지합니다.
